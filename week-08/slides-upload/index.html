Part 1

Why models overfit

Linear regression, too many features, and the bias–variance tradeoff.

Linear regression

A weighted sum of features

\( \hat{y} = b + w_1 x_1 + w_2 x_2 + \cdots + w_p x_p \)

Weights

What each feature does

A coefficient says how much the prediction changes when that feature goes up by 1, holding the others fixed.

Least squares

Only one goal

Make the squared training errors as small as possible. Complexity is not charged for.

Many features

Training error can look too good

Bias and variance

Two ways a model can be wrong

Models you know

Every dial you already turned

Rigid

High bias

Large K in KNN. Few features. A line that is too simple. Underfitting.

Balanced

Sweet spot

A moderate K. A moderate number of features. Useful on new data.

Wild

High variance

K = 1. Many features. A high-degree polynomial. Overfitting.

Interpretability

Explainable, or flexible?

Easier to explain

Lasso, ridge, linear models

Medicine, lending, and science often need to say which features drive a prediction, and by how much.

Harder to explain

KNN, trees, nets

When only accuracy matters and there is plenty of data, flexibility can win. Explanation is secondary.

Part 2

Ridge and lasso

Add a penalty for large coefficients.

The big idea

Fit the data, but pay for complexity

Three formulas

What each method minimizes

OLS

Least squares

\( \mathrm{RSS} \)

Only training error. No charge for large weights.

Ridge

L2 penalty

\( \mathrm{RSS} + \alpha \sum_j w_j^2 \)

Squares the coefficients. Shrinks them toward zero.

Lasso

L1 penalty

\( \mathrm{RSS} + \alpha \sum_j |w_j| \)

Absolute values. Can set some weights to exactly zero.

Ridge

Every feature stays, but smaller

Lasso

Some features are removed

Picture it

Corners give exact zeros

Which one

Ridge vs. lasso

No universal winner

Try both. Let cross-validation decide.

Elastic Net

A blend

ElasticNet mixes L1 and L2. Handy when groups of features move together.

The rule

Match the goal

Want a sparse model? Start with lasso. Expect many weak predictors? Start with ridge.

Part 3

In practice

Scale, choose alpha, then read the coefficients carefully.

Before you fit

Scale first. The penalty is blind to units.

Choosing alpha

Cross-validation turns the dial

In code

Let CV pick alpha for you

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LassoCV

model = make_pipeline(
    StandardScaler(),
    LassoCV(cv=5)
)
model.fit(X_train, y_train)
model.score(X_test, y_test)
model[-1].alpha_
model[-1].coef_

When it matters most

Many features, not enough rows

Lasso wins

Few features matter

It can drop the rest and leave a short list.

Ridge wins

Many help a little

Sharing the weight is stabler than deleting most of them.

OLS is fine

Lots of rows, few features

With a stable least-squares fit, the gain can be tiny.

Read carefully

A zero is not a proof

Zero ≠ unimportant

A dropped predictor may still matter. Its information may sit inside a correlated feature that stayed.

Nonzero ≠ causal

A surviving coefficient is a useful association in this model, not a cause-and-effect claim.

Classification

Logistic regression uses C

C is inverted

Small C = strong penalty

In LogisticRegression, C works the opposite way from alpha. Large C is closer to an unpenalized fit.

L1 or L2

Same story

L2 keeps every feature. L1 can remove predictors and make the model easier to explain.

A recipe

From split to a number you can defend

Pitfalls

Six mistakes to avoid

1
Forgetting to scale inside the pipeline.
2
Tuning alpha on the test set. That is leakage.
3
Reading a zero as “this feature never mattered.”
4
Mixing up lambda, alpha, and C.
5
Judging by training error. A penalty always looks worse there.
6
Expecting a huge gain when least squares is already stable.

Keep these

Six sentences

1
Overfitting is variance. Underfitting is bias.
2
Ridge shrinks. Lasso shrinks and can select.
3
Alpha trades a little bias for a lot less variance.
4
Scale inside a pipeline before you penalize.
5
Choose alpha with cross-validation, then test once.
6
A zero coefficient is not a causal claim.
